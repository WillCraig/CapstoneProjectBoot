# Responsive layout

The Angular UI was checked in headless Chrome, signed in as `agent`, at 360, 414, 768, 1024, 1280, 1440, and 1920 CSS pixels, plus phone landscape (740×360 and 896×414), tablet portrait and landscape, and a 640px-wide viewport standing in for 200% browser zoom on a 1280px laptop. Colors, type, copy, routes, and `data-testid` values are unchanged.

Shared tokens live in `frontend/src/styles.css`: `--page-gutter`, `--card-padding`, `--tap-min` (2.75rem), and `--content-max` (62.5rem). Media queries repeat three widths because they cannot read variables: 40rem (640px), 48rem (768px), and 64rem (1024px). Below 40rem the page gutter and card padding shrink. Below 64rem, nav links, profile links, and table actions are at least 44px tall. Buttons and fields are at least 44px at every width.

The header keeps “Northstar CRM” on one line and lets the nav wrap under it on a phone. Home choice cards use `repeat(auto-fit, minmax(min(100%, 17rem), 1fr))`, so a phone shows one column, a 768px tablet shows two, and a laptop shows the original three. Customer lookup keeps the table from 640px up. Below that, each row is a stacked card with the same Profile and Edit links. The create form shows the public-ID sentence in a wrapping field instead of a single-line input that was clipping it. Interaction headings and timeline rows wrap instead of overlapping around 640px, and rows stack below 768px. Login’s show/hide control is a 44px target. The viewport meta tag was already `width=device-width, initial-scale=1`.

Still not ideal: above 1024px the nav stays the original compact text so a projector view matches the old header. At 768px the third home card sits alone on the next row, and the interaction timeline stacks each field rather than keeping one tight row. A 360px header wraps Log out onto its own line. Wide screens stay centered (1000px, 900px, and 440px) instead of stretching to 1920px. Screenshots are in `frontend/responsive-screenshots/` and are gitignored.
